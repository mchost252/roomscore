Socket flow for status:

1. User sends message → optimistically set
status: 'sending'
2. Server confirms receipt → emit
'message:status' { id, status: 'sent' }
3. Recipient's device connects/receives →
server emits to sender: { id, status:
'delivered' }
4. Recipient opens the conversation →
client emits 'message:seen' → server
broadcasts to sender: { id, status: 'seen'
}

PERFORMANCE RULES (LOWBUDGET ANDROID)
These are non-negotiable for your target devices:

1. FlashList everywhere
Replace every FlatList with FlashList from
@shopify/flash-list.
import { FlashList } from "@shopify/flashlist"
// estimatedItemSize is required — measure
your average item height
<FlashList data={messages}
estimatedItemSize={72} renderItem={...} />

2. Memoize all list items
const MessageRow = React.memo(({ message })
=> { ... })

3. Keep all tabs mounted (pager-view)
For the main tab navigation, use react-native-pagerview with offscreenPageLimit :
<PagerView offscreenPageLimit={1}
initialPage={0}>
<HomeTab />
<MessagesTab />
<RoomsTab />
<MoreTab />
</PagerView>

This keeps adjacent tabs mounted so swiping feels
instant.

4. Single socket connection
Never create more than one socket connection.
Create it in useSocketStore on app launch, share it
everywhere. Disconnect on logout only.

5. Image optimization
import { Image } from 'expo-image'
React Native Image

// NOT

// expo-image has built-in caching,
blurhash placeholders, and faster loading
<Image source={{ uri: url }} placeholder=
{blurhash} contentFit="cover" />

6. Avoid re-renders
All Zustand selectors should be specific:
useStore(s => s.specificField) not
useStore()

Avoid putting large objects in state that changes
frequently
For message list, only append new messages —
never reset the entire array

7. Haptics cost nothing
import * as Haptics from 'expo-haptics'
// Only fire if setting is enabled
if (hapticsEnabled)
Haptics.impactAsync(Haptics.ImpactFeedbackS
tyle.Light)

8. Animations on UI thread
All Reanimated animations must use
useAnimatedStyle and useSharedValue — never

Animated from React Native core. Reanimated runs
on the UI thread and won't drop frames even on lowend devices.

NOTES
The "profile bottom sheet" you referred to is
actually a swipe-DOWN reveal — the chat slides
down to reveal the profile underneath.
@gorhom/bottom-sheet by default opens from
the bottom but can be used inverted. Alternatively
build it purely with Reanimated
PanGestureHandler for full control.
Room task thread chat (in-task chat) follows the
same logic as Room Chat expanded but scoped
to a specific task thread ID.

Room chat uses Outline bubble style always,
regardless of user's personal bubble preference.
Krios AI chat uses its own bubble style (dark card
with waveform indicator for AI, user's selected
style for user messages).
Android keyboard behavior differs from iOS — test
react-native-keyboard-controller on both.

Use KeyboardAwareScrollView as fallback if
needed.
